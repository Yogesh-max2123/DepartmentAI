## Dependencies before institutional use

- Approve and implement a trusted student programme identity/provisioning source.
- Define and approve exact portal application categories, required-document rules, eligibility policy/evaluator, source/version provenance, and reviewer workflow. Readiness remains blocked until this mapping can select a source without inferring from free text.
- Approve committee routing and formal deficiency request/response behavior before enabling those policy decisions.
- Provision an isolated Module II test database/profile and runtime-only synthetic grants/records before browser-to-backend data acceptance; do not activate institutional permissions or use institutional data.

The test-only synthetic identity and policy used by isolated tests are not production configuration. The inventory is based on source inspection and isolated test evidence only. No institutional database, account, provider, or export data was used. The authenticated knowledge API has an isolated database-backed test, but no browser-to-knowledge-endpoint verification has been performed. OCR remains unsupported; no OCR capability is claimed.
